# 容易混淆的责任与标签

只比较本案真实候选，不必每条穷举所有标签。解释应指出支持当前项的事实，以及相近项缺少的证据。

## 语义目标、grounding、命令、适配

1. 上游语义目标已经错：追溯产生错误语义的模块。下游坐标准确命中该错误目标，不是新的定位错误
2. 语义目标正确，但映射到错误控件/位置：grounding；检查原始模型定位输出及图像坐标空间
3. 控件目标正确，但动作类型、文本、按键、参数或代码表达错误：动作/命令生成；查看实际生成内容，不能只看异常类型
4. 上游动作符合当时契约，但缩放、归一化、按键解析、编码或下发出错：适配/Controller
5. 下发正确但App行为异常：用执行与App证据区分；页面没变化本身不能排除没聚焦、目标错误、转换错误等解释

命令行是操作形式，不是根因标签。shell路径、转义或语法错误可由生成命令的模块引入；pyautogui坐标也可能是grounding问题。没有真实坐标尺度、转换或下发证据，不把误点强定为适配器映射缺陷。

## UniPath Function

| 项 | 区分依据 |
| --- | --- |
| F1 Perception | 读错/漏掉直接可见的字、控件、图片或页面类型 |
| F2 State Estimation | 可见信息已被正确读到，但推断当前状态/进度错误 |
| F3 Goal / Constraint Understanding | 对用户要求本身理解错，如“前三个”被理解为任意三个 |
| F4 Planning | 目标和状态理解正确，策略、路径或下一动作选错 |
| F5 Target Grounding | 正确语义目标映射到了错误GUI对象 |
| F6 Action Formulation | 目标正确，动作类型、参数、文本或命令表达错误 |
| F7 Verification | 判断刚才动作是否成功或任务是否完成时出错 |
| F8 Memory | 跨步记录、更新、读取有具体错误证据 |
| F9 Device Execution | 上游正确动作未被忠实执行，有执行层证据 |
| E2 Task Precondition | 可核查的账号、内容、功能、匹配结果或业务条件不满足；不是模型模块错误 |
| E1 Environment | 正确观察、决策及执行后的App/环境异常，不等于所有前置不足 |

例：看到收藏标记却把“已收藏”误当“未收藏”可能是F1；读到红心但推断对应另一首歌是F2候选；把“收藏到test”理解成任意歌单是F3；理解对却选择不满足目标的路径是F4；把点击后未提交当作完成，重点查F7。不能靠出现“误认为”三个字决定标签。

## UniPath Mechanism

- incorrect_inference：已有可靠信息，被推出不成立结论；需指出具体信息和错误推论
- incorrect_assumption：把未经支持的前提当真；需写出该前提及缺证据之处
- incomplete_information_use：决策时已有相关信息，却遗漏使用；需证明该信息当时可获得，不能拿后续才出现的截图追责
- missing_verification：应核验且有机会，却跳过判断；缺最后截图不等于此项
- insufficient_verification：进行过核验但未覆盖关键对象/条件；需指出核验做了什么、漏了什么
- premature_commitment：信息尚不足时过早锁定并采取实质行动；需说明未解决的不确定性、当时可行的辨别方式及过早决策，不能把所有“最高/最热门”选错都套此项
- execution_mismatch：合理指令与实际执行不一致；需执行层证据，不是只要结果不对就选它
- invalid_action_parameterization：生成动作参数本身不合法/不匹配语义，区别于正确参数被错误转换

多项都能描述时选最接近有证据因果机制的一项，交代有竞争的候选。不以标签使用频率、字面相似或“看起来更严重”选择。对象维度填该错误真正作用的对象，例如user_constraint或action_parameter，不统一填task_completion_state。

## 上游偏离与环境阻塞

先区分“看见限制”与“限制是原任务的主要阻塞”。登录、授权或无内容提示是真实界面事实，但其根因位置取决于此前进入该应用、账号和对象的选择是否符合任务。有证据的上游选错导致后续限制时，分析错误由谁引入；正确路径上的独立限制仍可按预置问题处理。缺少应用身份或路径证据时，不硬填模型责任或预置根因。

## 结果判断与目标理解

某模块明确要求“不准新建，只能已有歌单”，而原指令允许新建，首先检查它是否擅自收紧目标约束；不能因为这段话位于Reflection就直接叫结果判断错误。若目标理解正确，只是把已打开的新建流程判作失败，则是结果评估候选。

## 最高、最热门、前N

按任务允许的范围寻找排序/榜单/可比较指标。局部可见最大不自动是全局最大；也不能无截图证据就假定一定存在“按评分排序”按钮。说明实际提供哪些排序/数值、模型用了哪些。榜单全是“—”不支持第一名结论，可能有预置问题；模型强行认定仍是独立错误。

## 弹窗与输入

正常广告增加步骤不自动是根因；核对是否合理处理、是否被持续循环拖延。max_steps失败仍按主要原因解释。输入一个字一步可能源于模型选择、动作契约或执行失败后的绕行，不能只凭慢就归适配器。

placeholder不是真实输入。确认颜色、光标、提交后结果及当时模块判断；清空后推荐词重现不等于清空失败。风险门控、unsupported_action、账号验证及真实业务失败分别取证，不用human_confirmation总名替代原因。

## 动作格式错误与已有执行标签

层级模板使用 `framework/executor/invalid_action_format`（Mobile-Agent）或 `framework/worker/invalid_action_format`（Agent-S2）。动作JSON或命令语法不成立、缺少必需结构，导致解析失败属于此项；有效动作的类型或参数值错误仍沿用wrong_action/wrong_parameter。坐标定位错仍用原Grounding/Executor标签；正确坐标被缩放错用Controller坐标映射；正确动作未下发用动作传输。不要把所有命令行错误或适配问题都归入动作格式错误。

核对原始动作与解析异常；Manager称格式错误仅证明其判断。只有控制台中不合法的动作字符串时，可确认日志输出格式错误，但缺少原始API响应与finish_reason时，不进一步断言模型生成、输出截断或服务处理是哪一环造成。解析器把合法输出错误拒绝属于执行适配候选。输出格式错不自动成为全任务主要根因。

UniPath用F6/invalid_action_format表示动作格式错误，Module按实际输出来源填写；不新增层级标签。
