# 逐Step启动Prompt候选：中文审核版

此文件用于阅读，不随启动Prompt一起发送。实际输入见同目录prompt_case001_optimized.txt，Skill仍为冻结的v3／0.15.2。

对当前attempt原生使用gui-trajectory-attribution，读取其必需引用、当前框架职责、任务口径和分类模板。原始证据只读，分析结果只写入当前工作区。不执行手机任务，不访问网络、GT、历史预测、其他模型或个人技能。完整result.json由调用方组装，模型不写旧的result.part文件。

任务身份随case注入。示例case001为Mobile-Agent-v3／Hard Intents／QQ音乐test_1：随机播放热门搜索中的一首歌，加入名为test的歌单。

## 1．读取材料

读取input_index、step_index、单步Schema和全局Schema。每张图库图片分别调用原生view_image，使用已冻结的缓存字节、保持原尺寸，不缩放、不拼图、不以OCR替代、不跳过重复图。图库序号本身不能证明动作步号及前后关系，不确定时保留限制，可做简短图片笔记。

完整读取独立日志页，以及后续每一步的日志页。每页单独调用exec_command，max_output_tokens至少32000，避免截断。文件清单和来源编号不等于内容。独立看图调用可每轮批量发出4—6个，独立规则和Schema读取也可并行，但每项必须完整送达。

## 2．逐Step判断与提交

按step_index的数字顺序处理。判断前读完本步日志，结合原始任务、先前观察、模块输出、实际动作与UI变化，填写单步Schema：局部判断reasonable/error/uncertain、简短过程与理由、观察结果和不确定处，通常附1—3项证据。合理探索、缺少结果或时序不明时保留不确定。

记录直接图像事实，包括最后一帧，但不编造动作或图像时序。source_id来自索引，phase表示时序而非规划／验证阶段，证据类型由程序绑定。局部错误不等于最终根因。

基础步骤文件只通过io.ps1的step模式提交。助手检查下一待提交步骤，返回证据编号；不改助手、不手动覆盖已提交记录。按英文Prompt提供的PowerShell多行字符串示例传入小JSON。

同一时刻只提交一步。保存当前步和读取下一步日志可同轮发出，但必须等当前步保存成功、下一步材料返回后，才判断下一步。保留局部拒绝记录，纠正仍待提交的内容。

## 3．全局归因

全部图片、日志和步骤记录完成后，集中读取过程判断，结合后续纠正及观察到的预算损失比较候选原因。先明确错误语义，再根据实际输出确定责任，最后选合法标签；不机械取最早异常，不把执行上游错误计划自动归为执行器问题。

Recovery需要可观察的机会和独立缺陷。污染、预置问题和处置沿用Skill规则；保留事实与真正的不确定，不能为通过检查而改写。

确定的目标状态需要直接截图或执行结果支持，模块自述不够。命令生成责任要有同一步原始输出。引用助手返回的证据编号，字段、枚举和null按Schema填写。

重大因果疑点最多做两批针对性原材料回查，不重新通读全轨迹。新读到的直接证据可追加到step_judgments/revision_NNN.json；原步骤、原verdict及原证据前缀不变，并在limitations说明。不得按预期答案改记录，也不能为了省时间把全部目标改成unknown。

使用io.ps1的global模式提交全局结果，按全局Schema填写，不重复由调用方构建的evidence、process和coverage。

## 4．检查与结束

运行一次io.ps1的check模式。失败时，在允许的提交或追加修订范围内定向纠正一次，再检查一次，保留原始步骤记录。这是基础检查，不安装依赖、不另写校验器、不自行执行最终严格校验。

调用方完成后严格校验一次，不再向模型反馈修复。必需文件齐全且基础检查通过后，仅回复DONE；仍有阻塞则如实说明。局部纠正保留记录，不算零错误输出。
